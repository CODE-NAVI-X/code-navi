# 投稿前检查

## 版本

`submission-readiness.v1`

## 用途

在用户保存投稿准备档案并明确点击后，对当前本地已保存的初稿、修订预览、审稿意见和证据状态生成检查清单；它不判断录用概率、投稿资格或任何特定 venue 的合规性。

## 输入与输出

输入为用户主动保存的 `SubmissionProfile`（目标投稿方向、匿名、篇幅/章节、伦理/数据要求及备注）、`PaperDraft`、最近 `PaperReview`、最近 `PaperRevision` 及是否已有实验/学术证据；输出为可恢复的 `SubmissionReadinessCheck`，含 `not_ready / needs_review / checklist_complete`、阻塞项、警告、人工核验项、档案快照和事实边界说明。

## 规则层与模型层边界

规则层负责投稿档案保存/恢复、章节、占位符、未核验主张、已确认匿名要求下的身份线索、伦理/数据许可、材料与 venue 格式提示，以及状态判定。当前不调用模型；任何未来模型只能优化说明，不能将 `to_verify` 改为事实、猜测 venue 要求或宣称“可以投稿”。

## 权限、来源与副作用

不联网、不读论文全文、不写入用户项目、不安装依赖、不执行代码、不投稿。只读取当前本地会话的已保存工件与用户保存的档案；保存档案和运行检查都需要用户显式操作，结果仅写入应用 SQLite 以支持会话恢复。

## 失败与规则降级

没有投稿档案、目标 venue、修订预览、实验记录或受限来源证据时返回明确的 `to_verify` 项；不会补造引用、实验结果、伦理许可或目标 venue 合规结论。

## 测试样例

含“显著提升”且无实验事实的草稿会得到 `not_ready` 与 `to_verify`；未填写目标投稿方向会显示“待用户确认”；已选择匿名且草稿含身份线索会显示阻塞项；刷新后可恢复档案和检查；未生成修订预览时明确列为阻塞项。

## 外部参考与许可证

遵循本项目的事实边界和用户确认原则，不复制外部投稿检查框架、模板或 Prompt；无新增第三方依赖。
