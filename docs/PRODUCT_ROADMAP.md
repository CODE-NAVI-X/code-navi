# 产品路线图

## 产品定位

Code Navi（智教码航）面向计算机专业人才培养，覆盖助学、助教和助研。产品使用独立的 `code-navi-kernel` 运行单 Agent，把业务提示、流程、工具和人工复核保留在应用仓库。

## 当前基线

截至 2026-07-15，以下仓库级工作已完成：

- Code Navi 与 kernel 的仓库职责已经拆分；
- 应用依赖固定到已完成的 kernel 提交；
- 三个领域各有最小 Agent 声明；
- 离线 MockProvider 示例和集成测试可用于接线验证；
- 开发、架构和 kernel 升级规范已经进入 `docs/`。

当前基线不是完整产品，也不代表真实模型、Web、数据源或多 Agent 能力已经上线。

## P1：可运行的最小应用入口

目标：让开发者通过一个受控入口选择领域 Agent，并完成一次可审计的离线或显式配置的 Provider 运行。

计划范围：

- 最小 CLI 入口和清晰的错误码；
- 配置装配、Provider 选择与密钥环境变量校验；
- run/session 标识和 Event 日志目录；
- 三个领域的输入校验、输出约定和人工复核提示；
- 离线默认测试以及 opt-in 在线冒烟测试。

验收：全新环境可按 README 安装；无凭据时仍可运行 Mock 示例；真实 Provider 只在显式配置后启用；三类 Agent 均经 `AgentRuntime` 运行并产生可定位的 Event。

## P2：三组最小业务闭环

目标：为每个领域建立一个可人工复核的窄流程。

| 领域 | 最小闭环 | 必要复核 |
| --- | --- | --- |
| 助学 | 学习目标/代码片段 → 分步提示、自检条件和下一步练习 | 教师或助教确认范围和答案边界 |
| 助教 | 教学目标/作业要求 → 材料或评分提示草案 | 教师确认准确性并负责发布 |
| 助研 | 研究问题/已有证据 → 计划、假设、证据缺口 | 研究者核验来源、方法和结论 |

每个闭环都需要：可追踪输入、明确失败条件、至少一组离线回归样例、人工确认点以及不确定性标记。

## P3：受控工具、数据与评估

在 P2 经过实际人工验证后，逐项增加资料检索、工作区读写或其他领域工具。每个工具必须显式注册、最小授权并有独立失败测试。同步建设质量评估、基线数据、回归门和错误分类，不把模型主观判断作为唯一验收。

## P4：产品化与扩展验证

在前述契约稳定后，再评估身份权限、服务化入口、部署、更多 Provider、运行观测和跨角色协作。多 Agent、自动评分和自动发布必须独立立项，不从单 Agent 基线自然推定为可用。

## 路线图规则

- 每一阶段只有通过书面验收后才能标记完成。
- 范围变化必须同步更新架构、不变量、非目标和测试计划。
- 涉及高风险外部操作时，先定义确认、审计和回滚，再实现功能。
- 路线图描述计划，不替代 issue、设计文档或 PR 中的具体实现证据。
