# 外部科研 Skill 试用与适配评估

定位：历史评估记录。本文保留候选选型与适配依据，不定义当前产品行为；当前 Research 主流程以 [产品范围](product/scope.md) 和 [系统架构](architecture/system.md) 为准。

## 目的与边界

本次评估只在隔离目录 `%TEMP%\\code-navi-external-skill-trials` 完成；未运行安装脚本、未把外部 Skill 写入 Codex 全局目录或本仓库、未配置外部 Key，也未执行外部命令。目标是判断哪些**思想**可以改善现有闭环，而不是以外部框架替换已验证的会话、权限或事实边界。

评估完成时的闭环已经包含可恢复的对话澄清、规则计划、用户主动的受限学术检索与 EvidenceBundle、难点分析、实验方案、确认后的只读代码草案以及思维导图。因此，不重复接入这些能力。当前主流程已经使用动态 ResearchProfile；原五字段 `research_sessions` 只保留为兼容 API。

## 同输入离线试用与对比

试用不调用真实模型或任何外部 API。对现有离线规则流程运行同一组输入；对已克隆的 Socratic 文档作**指令级干跑**，用原创中文问题检查其策略是否适配。这样既实际试用了候选的工作流约束，又不会把外部多 Agent、联网或命令执行引入本地演示。

| 测试输入 | 当前系统的安全表现 | Socratic 策略的可借鉴点 | 适配判定 |
| --- | --- | --- | --- |
| “我想研究生成式 AI 对大学生 Python 编程学习反馈的影响，但不知道如何确定研究问题。” | 保存明确主题；继续询问对象/场景，允许自由输入和三个建议项 | 可先追问“学习反馈”将以何种可观察结果界定，再进入场景与方法 | 采用为模型追问的优先顺序，不改变字段和完成条件。 |
| “我不知道应该如何选择数据与方法，有什么推荐吗？” | 作为不确定性处理；只有经校验的模型建议可补字段，不能把“不知道”写成事实 | 可问“用什么可观察差异判断一种数据/方法更合适”，把决定权留给学生 | 采用一次一问、说明依据的提问方式；规则兜底与推荐项保持原样。 |
| “我只有两周、约 30 名学生、没有 GPU，只能使用匿名学习记录。” | 将时间、样本、设备和材料限制标为用户已确认条件；不声称数据足以支持结论 | 可追问“若结果不稳定，如何区分样本限制和真实无差异” | 采用资源可行性/替代解释检查；任何样本量、指标或结果仍为 `to_verify`。 |

### 指标结论

| 指标 | 现有模块 | 外部候选 | 最终决定 |
| --- | --- | --- | --- |
| 追问贴合上下文 | DeepSeek JSON 成功时可做到，离线规则稳定 | Socratic 模式在定义、证据、替代解释和可行性上更有启发 | 仅吸收该四类提问策略。 |
| 自由输入、动态画像与会话恢复 | 已由应用规则和数据库保证 | 外部 Socratic 多层流程不以本项目 ResearchProfile 为核心 | 保留现有规则，不替换。 |
| 自动联网或越权 | 仅用户主动调用允许来源 | qinyan 会调用其 API；deep-research 有资料协议/多 Agent 扩展 | 不接入外部执行路径。 |
| 事实边界与降级 | `fact / inference / to_verify`、无模型规则降级已经可测 | 候选强调证据但依赖其工作流/资料获取 | 继续由本项目 schema 与校验承担。 |
| 代码草案安全性 | 确认门槛、合成数据、仅预览、禁止安装/执行 | scikit-learn 候选包含安装和运行示例 | 不直接接入，仅用结构检查清单复核现有模板。 |

## 最小适配

已在 `research-clarification` 的本地 Skill 契约中加入**苏格拉底式提问约束**：模型在动态画像的当前缺口内，一次只追问一个未确认维度，并按“定义/可观察性 → 证据或数据 → 替代解释 → 资源可行性”选择最贴近上下文的问题。它不生成完整研究问题、不强迫回答、不决定画像字段顺序、不自动联网，也不替代三项推荐或规则降级。

实验代码草案没有改变运行时代码：现有固定模板已经包含 README、合成数据、基线、评测和待验证项。外部候选的安装、训练和执行内容被明确排除。
