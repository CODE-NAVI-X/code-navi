# EvoScientist 实验闭环设计笔记

## 来源与阅读范围

- 论文：Yougang Lyu 等，*EvoScientist: Towards Multi-Agent Evolving AI Scientists for End-to-End Scientific Discovery*，arXiv:2603.08127，2026-03-09。
- 已核验来源：[arXiv 摘要页](https://arxiv.org/abs/2603.08127)。本机 Desktop 与 Downloads 中未发现同名 PDF，因此本笔记只基于该摘要页，不声称已精读全文或复现实验。
- 本文是本地设计依据，不是运行时 Skill、Provider、Tool 或论文代码来源。

## 论文直接支持的事实

1. 论文将系统描述为三个角色：研究想法生成的 Researcher Agent、负责实验实现与执行的 Engineer Agent，以及提炼可复用经验的 Evolution Manager Agent。
2. 摘要明确列出两类持久记忆：记录可行/失败方向的 ideation memory，以及记录数据处理、模型训练策略与最佳实现线索的 experimentation memory。
3. 摘要称该系统以自动和人工评价比较想法的新颖性、可行性、相关性和清晰度，并报告代码执行成功率改善。

## 对当前项目的设计推断

1. 当前项目可将“研究画像、规则计划、EvidenceBundle、待验证项”看作可追溯的轻量上下文，而不需要多 Agent 记忆系统。
2. 实验方案应先把假设、资源、指标、风险和导师确认项写清；代码草案只预览，不执行。这样保留“提出—核验—修正”的闭环思想，同时把实验执行交还给学生和导师。
3. 对每次人工测试可保留“已确认条件、失败/不确定原因、下一次要核验的项目”，但不能把模型建议或未跑实验的结果升级为事实。

## 仍需验证

1. 仅凭摘要无法确认论文中各基准、评价协议、统计显著性、失败案例和安全控制的完整细节。
2. 当前项目尚未验证可复用的实验记忆是否提升学生研究质量；若后续评估，应由用户同意的匿名、可审阅记录和明确指标支持。
3. 当前项目不能据此自动运行代码、下载数据、安装依赖、写文件或自主迭代实验。

## 明确不采用的部分

不引入论文的多 Agent 编排、自动实验实现/执行、自演化或长期执行记忆。它们需要额外的权限、资源隔离、审计、成本和安全验证，超出本地科研辅助演示的范围。
