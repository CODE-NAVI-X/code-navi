# 科研端全内容 LLM 生成设计

## 目标

科研端所有面向用户的科研文本均由已配置的大模型生成；规则代码只负责状态、准入、结构校验、事实边界和来源范围。

## 范围与数据流

开场引导、研究计划、对话回复、方向难点、实验方案、复现方案、论文分析、思维导图、论文蓝图及审稿/改写建议统一经过结构化 LLM 生成器。生成器接收当前已保存画像、研究计划上下文和允许的 EvidenceBundle，返回带 `generation_mode=llm`、`run_id`、来源范围及 `fact/inference/to_verify` 分类的 JSON。服务端校验后持久化，刷新只读取已保存结果。

规则层继续计算画像完整度和下一阶段准入，并拒绝越界事实、缺失字段和非法分类；规则层不再生成用户可见的欢迎语或研究计划正文。

## 失败与成本边界

模型不可用、超时或输出校验失败时返回结构化错误，页面显示重试和已保存内容，不使用规则模板替代。首次生成和重试均由用户触发；GET/刷新不调用模型。测试使用 Fake Provider，真实 DeepSeek 仅由用户主动操作触发。

## 验收

1. 新会话开场和完整画像研究计划的 `generation_mode` 均为 `llm`。
2. 模型失败不会产生 `rules_fallback` 或伪造的规则正文。
3. 刷新会话恢复相同的生成结果和审计标识，不重复调用模型。
4. 现有阶段准入、来源边界和事实分类测试继续通过。
