# 产品状态与交付路线

## 1. 当前实现基线

执行任务时以实际代码、测试和运行结果为准。当前仓库的能力边界如下：

| 能力 | 当前状态 | 实际范围 |
| --- | --- | --- |
| Kernel 与 CLI | 本地可运行 | `code-navi ask`、`code-navi shell` 经 `AgentRuntime` 使用 Mock、OpenAI 或 DeepSeek Provider，并保存 Event JSONL |
| 知识点学习 | 本地闭环已实现 | FastAPI 与 Next 页面可提交知识点；模型调用经 Runtime；结果写入按学习会话隔离的 SQLite 笔记 |
| 科研助手 | 本地闭环已实现 | 动态研究对话、画像与消息恢复、检索计划，以及用户确认后的 OpenAlex、Crossref、arXiv 元数据与摘要检索；模型不可用时回退到规则 |
| 代码测试练习 | 页面占位 | 页面可接收原型上下文；没有后端任务、执行器或测试反馈闭环 |
| 跨模块上下文 | 浏览器原型 | `FlowPayload` 仅在当前前端进程内接力；刷新后丢失，用户查看、修改、清除和服务端持久化未完成 |
| Web/API 宿主 | 本地开发可用 | Next 前端、FastAPI、`/health`、显式 CORS allowlist 和本地启动脚本已存在 |
| 业务持久化 | 本地可用 | 学习笔记、兼容科研会话、动态对话和证据共用 SQLAlchemy Base；Alembic 管理当前 schema |
| Docker | CLI 验证基线 | 当前 Compose 只运行 CLI，不打包或暴露 Web/API |
| 生产 Web 服务 | 未实现 | 缺少身份授权、版本化 Web/API 产物、生产数据方案、监控和已验证回滚 |
| 代码执行与仓库写入 | 未实现 | 不得描述为可用能力 |

## 2. 当前优先事项

### 2.1 收敛已有本地闭环

1. 保持所有 ORM schema 变化同步新增 Alembic revision，并验证空库和受影响旧库升级；
2. 保持学习、科研、CLI 的 Provider 配置和错误语义一致；
3. 明确 Runtime Event、学习会话、科研对话和兼容科研会话标识的职责；
4. 补齐跨模块上下文的查看、修改和清除，再将其标记为可用产品流程。

### 2.2 完成代码练习最小闭环

先用 Mock 执行器定义请求、结构化结果和错误分类，再在隔离环境运行固定可信示例。资源限制与安全边界未验证前，不接收不受信任代码。

完成条件：

1. 前端或 API 能提交一个固定练习；
2. 执行结果只能来自执行器；
3. 成功、编译错误、运行错误、超时和系统错误可区分；
4. 相关 Event、测试和用户可见状态一致。

### 2.3 生产化 Web/API

现有本地 Web/API 不等于可生产部署。进入生产前补齐身份与授权、跨设备会话、版本化构建、数据库备份与恢复、速率限制、监控和隔离环境回滚验证。具体准入见 [生产准入](../deployment/production.md)。

## 3. 条件推进能力

在线代码执行、远程仓库写入、新增全文或付费资料源、多 Agent、自动评分和自动发布分别建立独立最小闭环，不因现有 Web 页面或在线 Provider 可用而自动获得权限。

## 4. 状态更新

1. 路线按实际运行结果推进，不以页面存在、接口草图或模型输出代替闭环。
2. 每次只更新受影响能力，不要求三个模块同步达到相同成熟度。
3. 状态使用根 [AGENTS.md](../../AGENTS.md) 定义的“原型完成”“本地验证完成”“合并就绪”和“生产可用”。
4. 稳定产品边界变化时同步检查 [scope.md](scope.md)。
