# 科研论文辅助本地演示检查表

本文只用于本地演示与回归核对。所有内容都是建议或待核对项，不代表导师意见、同行评审结论、实验事实或投稿资格。

## 演示前置条件

- 在仓库根目录使用 Python 3.11+、Node 20.19+，并完成 `.[dev,server]` 与 `frontend` 依赖安装；不需要真实模型密钥。
- 执行数据库迁移；演示数据只保存在本机 SQLite。不要展示或提交 `.env`、Key、数据库、缓存或论文全文。
- 可选配置 DeepSeek 只用于个性化表达；无 DeepSeek Key 时应明确展示基础规则或规则降级，而不是中断会话。
- 检索必须由演示者手动点击；引用面板只读取此前已保存的 EvidenceBundle，绝不自动联网补全。

## 本地启动命令

```powershell
.venv\Scripts\python.exe -m alembic upgrade head
python scripts/dev.py
```

打开 `http://127.0.0.1:3000/research`；后端健康检查为 `http://127.0.0.1:8000/health`。

本清单演示独立进入 Research 的当前 Capability-first 路径。Research 尚未接入持久工作区；接入后另行增加 Activity 关联与恢复检查。

## 导师演示路径与检查点

| 步骤 | 用户主动操作 | 预期展示内容与事实边界 |
| --- | --- | --- |
| 1 | 输入模糊研究想法并完成动态 ResearchProfile 澄清 | 恢复后的 ResearchProfile、规则研究计划；`fact` 仅是用户确认输入，建议为 `inference`，未知为 `to_verify`。 |
| 2 | 点击受限学术检索，并选择 arXiv 或当前允许来源 | EvidenceBundle 显示来源、访问时间、元数据/摘要范围和失败状态；没有点击时不自动联网。 |
| 3 | 打开已保存证据 | 仅将标题、作者、年份、链接和摘要直接范围视作 `fact`；关键词相关性是 `inference`，摘要外内容保持 `to_verify`。 |
| 4 | 粘贴实验设置、结果、失败原因和待确认项 | 实验结果证据包标明“用户提交事实（未独立复核）”；系统不读私有文件、不运行代码。 |
| 5 | 生成论文蓝图 | 六章写作目标、已保存证据、缺口、禁止主张和就绪度；没有证据时应显示待补充，不能补造实验结果。 |
| 6 | 粘贴 Markdown 或纯文本初稿并生成结构化审稿 | 审稿提示结构缺失、证据缺口和越界主张；“显著提升”等无记录支撑的文字必须为 `to_verify`，而非事实。 |
| 7 | 接受一条 RevisionTask，生成逐段候选改写 | 显示原文片段、候选、依据、信息范围和待验证项；候选改写是建议，不自动覆盖 PaperDraft。 |
| 8 | 接受候选或手动编辑后保存 | 创建新的 PaperRevision，并显示父版本、任务/建议 ID、变更理由和 diff；原稿与历史版本保留，可在刷新后恢复。 |
| 9 | 在引用面板主动选择一条已保存来源和目标章节 | 生成引用占位与参考文献雏形；仅使用 EvidenceBundle，绝不自动选择、插入或改写原稿。缺作者、年份、DOI 或链接时标为 `to_verify`。 |
| 10 | 运行投稿前检查，再点击导出 | 检查匿名、伦理、引用、材料、格式等缺口；用户主动导出的 Markdown / JSON 辅助包只含已有文本，不含 Key、`.env`、数据库、论文全文或本地路径。 |
| 11 | 刷新页面 | 会话、实验记录、PaperRevision 版本链、引用选择和参考文献雏形可恢复；没有自动写入、自动安装依赖、自动执行代码或自动投稿。 |

## 失败降级演示方法

- **无 DeepSeek Key**：在不配置 `DEEPSEEK_API_KEY` 的终端启动。澄清、蓝图、审稿、候选改写仍走基础规则；页面不得伪称模型已成功。
- **检索无结果或来源失败**：提交窄查询或暂时断开网络。EvidenceBundle 应显示来源状态与空安全结果，不伪造论文。
- **元数据不完整**：选择作者、年份、DOI 或链接缺失的已保存来源。占位与参考条目必须保留待核对标记，不联网补全。
- **初稿或修订前置不足**：提交超长/不支持格式，或不接受 RevisionTask 就请求候选。系统应给出明确错误，不能创建 PaperRevision。
- **缺少实验记录、计划、证据或引用**：论文蓝图、审稿、引用和投稿前检查应列出缺口或返回安全空结果；不得为了演示完整度虚构数据。

## 已知限制

- 当前没有论文全文下载与精读、自动检索、自动写入项目；系统不自动写入、不自动安装依赖、不自动执行代码、不自动投稿。
- 引用占位与参考文献雏形仅供作者或导师核对，不支持完整 BibTeX、引用格式自动校验、期刊模板或 DOCX/PDF/LaTeX。
- 导出是用户主动触发的 Markdown / JSON 辅助包，不是最终投稿包；当前没有生产级文件存储或隐私托管。
- 本地闭环不替代导师审核、同行评审、伦理审批、数据许可检查或投稿规范核验。

## 导师可选择的下一阶段方向

1. **正式导出**：在独立阶段评估受控 DOCX/PDF/LaTeX 输出与渲染核验。
2. **投稿适配**：在独立阶段增加目标 venue 的人工确认模板与格式检查边界。
3. **文献管理**：在独立阶段设计可追溯的引用格式、BibTeX 与人工核验流程。
4. **实验材料整理**：在独立阶段设计用户主动上传、隐私边界与可复核材料索引；不得自动读取本地文件。
