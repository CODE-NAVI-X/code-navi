### 2.2 数学公式渲染全链路修复（Legacy 格式与 Markdown/KaTeX 统一） (P0)
- **优先级**：`P0`（视觉 Bug 治理）
- **负责角色**：苏育 / 梓柯
- **会议原旨与决策**：
  - 核心发声：“我看到一个 bug，这边的公式要给他转成一个... 这边的公式有的渲染出来了，有的没渲染出来... 是因为模型输出的代码格式（Legacy 格式）与前端不一致，它输了一个别的格式的代码，那它就不能渲染了。”
  - 要求：统一输出规范，前端全面支持 Markdown 与 LaTeX 标准公式，确保知识学习、练习题干、选项与解析中的公式 100% 正常显示。
- **关联代码与根因**：

  - [MarkdownText.tsx:L1-L73](file:///E:/codenavi/frontend/components/research/MarkdownText.tsx#L1-L73)（完全没有引入 KaTeX 或 MathJax，纯文本正则切片，导致科研模块对话中的学术公式全部原样显示为原始代码）。
  - [SlideRenderer.tsx:L106-L127](file:///E:/codenavi/frontend/components/learning/presentation/SlideRenderer.tsx#L106-L127)（`TextBlock` 仅使用 `sanitizeHtml`，遇到含 LaTeX 的文字节点不会调用 KaTeX）。
- **具体改进方案**：
  1. **前端通用数学渲染器**：封装统一的 `MathMarkdown` 组件，基于 `katex` 支持：
     - 行内公式：`$ ... $` 与 `\( ... \)`；
     - 块级公式：`$$ ... $$` 与 `\[ ... \]`；
     - 容错处理：当 KaTeX 解析异常时优雅退回源码，不崩解 DOM。
  2. **全面替换渲染挂载点**：
     - 在 `QuizView.tsx` 的题干、选项 `option.label`、解析 `analysis` 中使用统一公式解析；
     - 在 `MarkdownText.tsx`（科研对话）与 `SlideRenderer.tsx`（PPT 讲义文字框）中引入行内 KaTeX 拦截替换。
  3. **后端 Prompt 严格格式规范**：在 `quiz/prompts.py`、`conversation_prompt_templates.py` 中明确加入 System 规范：“所有数学公式必须使用标准 LaTeX 格式（行内使用 `$公式$`，独立公式使用 `$$公式$$`），严禁使用 HTML `<sub>`/`<sup>` 或 Word OMML 遗留格式。”
- **人工待确认/不清楚事项**：

## 模块五：科研模块与论文检索优化（Research & Academic Search）

### 5.1 论文检索相关性治理：修复中文分词缺陷与无关文献过滤 (P0)
- **优先级**：`P0`（重大演示质量事故治理）
- **负责角色**：陈盛漳 / 梓柯
- **会议原旨与决策**：
  - 会议惨烈故障复盘：“论文检索试出来有问题... 会出现很多不相关的，问注入攻击，出来好多什么中国人口之类的各种各样奇怪的东西... 简直差太远了！”
  - 要求：先从用户输入中提取核心 Keyword，基于 Keyword 检索，严格保证检索结果的相关性，尤其是中文与专业领域的准确性。
- **关联代码与根因**：
  - [academic.py:L613-L614](file:///E:/codenavi/src/code_navi/research/academic.py#L613-L614)：
    ```python
    def _tokens(value: str) -> set[str]:
        return set(re.findall(r"[a-z0-9]+", value.casefold()))
    ```
    **【致命 Bug 根因】**：分词函数 `_tokens` 使用正则表达式 `[a-z0-9]+`，**彻底过滤掉了所有中文字符**！当用户搜索“注入攻击”或“光线追踪”时，`query_tokens` 返回空集合 `set()`，导致相关性匹配得分、标题重合度、关键词重合度全为 0！排序逻辑完全失效，OpenAlex 只能依靠模糊单字或返回任意无关中文论文（例如“中国人口”）。
  - arXiv API 本身不支持中文分词检索，传入中文直接导致 arXiv 检索不到任何文献。
- **具体改进方案**：
  1. **支持中文字符与 N-gram 分词**：修改 `academic.py` 中的 `_tokens`，引入中文字符匹配或 2-gram 切分：
     ```python
     def _tokens(value: str) -> set[str]:
         # 提取英文数字单词
         en_tokens = set(re.findall(r"[a-z0-9]+", value.casefold()))
         # 提取中文单字及双字组合 (2-gram)
         cn_chars = re.findall(r"[\u4e00-\u9fa5]", value)
         cn_bigrams = {cn_chars[i] + cn_chars[i+1] for i in range(len(cn_chars)-1)}
         return en_tokens | set(cn_chars) | cn_bigrams
     ```
  2. **双语关键词自动翻译抽取（Keyword Extractor）**：
     - 在发起检索前，增加一步轻量关键词预处理：将中文核心词映射为其英文学术对应词（如：“注入攻击” -> `injection attack`, `SQL injection`, `prompt injection`；“光线追踪” -> `ray tracing`, `path tracing`）；
     - 将翻译后的英文检索词发送给 arXiv 与 Crossref，将中英文组合发送给 OpenAlex。
- **人工待确认/不清楚事项**：
  > [!IMPORTANT]
  > 是否引入轻量中英文映射词表（针对演示主题如注入攻击、光线追踪、CNN 建立规则词典），还是每次检索前调用一次 LLM 抽词？（强烈建议：针对演示主题配置保底静态双语关键词，避免额外一次网络请求延迟）。
