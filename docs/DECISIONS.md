# 架构决策记录

## 已确认决策

### ADR-001：应用与 Kernel 分仓

- 状态：Superseded by ADR-003
- 日期：2026-07-15
- 决策：`code-navi` 只维护产品与应用代码；`code-navi-kernel` 作为固定提交的外部依赖接入。
- 原因：避免两份运行时实现漂移，让产品迭代与通用执行语义分别评审和发布。
- 影响：kernel 契约变更必须走独立升级 PR；应用需求不能通过复制或修改 kernel 源码快速绕过边界。

### ADR-002：通用助手与任务上下文入口

- 状态：Accepted
- 日期：2026-07-18
- 背景：产品定位从固定的助学、助教、助研入口调整为通用代码学习助手；用户不应通过内部能力名与产品交互。
- 决策：新增一个默认无工具权限的通用助手。CLI 以自然语言问题为入口，装配受预算限制的项目上下文，并用一次性快问和临时问题分支表达 GUI 侧边栏的焦点变化。原三个领域 Agent 暂时保留为兼容导出，不再作为 CLI 入口。
- 备选：继续让用户选择领域 Agent；直接暴露 Skill/Tool 名称；把完整项目和历史无条件发送给模型。
- 影响：后续 Tool、Skill 和 Workflow 由应用按任务选择并独立授权；CLI 与未来 GUI 可以共享 ContextSlice 等应用契约。真正的持久化多轮会话仍需要独立设计。

### ADR-003：应用与 Kernel 同仓交付

- 状态：Accepted
- 日期：2026-07-18
- 背景：分仓依赖要求开发机和部署服务器在构建时访问私有 GitHub 仓库，增加了凭据分发、Docker Secret 和构建失败面；当前两个仓库由同一项目维护。
- 决策：将 `code-navi-kernel` 提交 `77e7c9e1898f94c42d1fbfcd7bb393a6ce1cb481` 的 `kernel` 包和测试并入本仓库的 `src/kernel/` 与 `tests/`，移除 VCS 依赖。代码仍保持 `code_navi -> kernel` 的单向依赖和公开接口边界。
- 备选：继续使用 BuildKit Secret 拉取私有仓库；发布私有 wheel；使用 Git submodule。
- 影响：安装和镜像构建不再需要 GitHub 凭据，版本可以原子发布；kernel 修改也进入本仓库评审，因此必须用目录边界、契约测试和独立变更范围防止业务逻辑侵入 core。

### ADR-004：CLI 以轻量 Compose 容器交付

- 状态：Accepted
- 日期：2026-07-18
- 背景：服务器需要使用一条 `docker compose up --build` 命令构建并拉起完整项目，当前产品只有 CLI，不需要 HTTP、反向代理或数据库。
- 决策：使用 `python:3.11-slim` 多阶段镜像，Compose 只编排一个非 root CLI 容器；项目目录只读挂载，Event 写入独立 volume，在线 Provider 通过运行时环境变量配置。
- 备选：Alpine 单阶段镜像；增加常驻 Web 服务；由服务器从私有仓库构建 kernel。
- 影响：部署组件少、无端口和额外守护进程；交互 Shell 依赖前台 TTY，未来增加 Web 宿主时需另行设计服务入口和健康检查。

### ADR-005：科研澄清采用应用层持久对话与动态画像

- 状态：Accepted
- 日期：2026-08-03
- 背景：既有科研页面要求用户按固定顺序填写五个字段，无法自然处理一轮多信息、方向纠正、模糊探索和候选问题比较；同时，科研会话需要刷新后恢复，但业务状态不应进入 Kernel Event 语义。
- 决策：在 `code_navi` 应用层新增 `/api/v1/research/conversations` 和 `research_conversations` 表，保存动态 `ResearchProfile` 与完整消息。在线对话决策由无工具的 `research_conversation_agent` 经公开 `AgentRuntime` 运行；模型只产生严格校验的 patch 和下一步建议，应用 reducer 决定持久化结果。无 Provider 或失败时使用确定性规则降级。成熟度是可解释建议，不是固定必填门禁。旧五字段接口在前端迁移期间继续兼容。
- 备选：继续扩大固定问卷；直接从 Web service 调 Provider SDK；把科研画像写入 Kernel Event；引入 LangGraph 等新的工作流运行时。
- 影响：对话更接近通用 Agent 交互并保留 Kernel 审计关联，且不会因模型或网络故障丢失会话；代价是应用数据库新增 JSON 状态，需要后续明确迁移与旧接口弃用周期。API 响应使用 `research-conversation.v1` 显式标记契约版本；持久化 JSON 继续由 Pydantic 校验，出现跨版本数据迁移需求时必须增加数据库迁移。

### ADR-006：本地模型密钥使用项目内忽略文件配置

- 状态：Accepted
- 日期：2026-08-03
- 背景：科研对话需要可选在线模型；纯环境变量和隐藏命令虽安全，但本地演示用户无法确认粘贴状态，并且服务已启动时新配置不会立即替换进程中的旧值。
- 决策：保留 `code-navi configure-provider`，同时为单机开发提供只接受回环地址请求的 Web 配置入口。表单使用密码框，Key 只随本机请求发送一次；服务端校验后原子写入项目内 Git 已忽略的 `.code-navi/provider.env` 并立即更新当前进程。响应永不回显 Key，浏览器不写 localStorage，保存后清空输入。状态和显式连接测试返回无密钥诊断。部署环境继续使用宿主环境变量或外部密钥管理。
- 备选：只保留 CLI；提交 `.env`；SQLite 明文保存；允许远程网页直接写配置。
- 影响：本地演示可以在页面完成配置和验证，代价是 Key 会短暂存在于浏览器内存和 localhost 请求体。该入口不是生产凭据管理：公开部署必须禁用或替换为身份认证、TLS、受限 CORS、CSRF 防护和专用密钥管理。项目目录仍属于敏感边界，不能上传配置文件。

### ADR-007：科研检索采用显式计划、来源白名单与可恢复 EvidenceBundle

- 状态：Accepted
- 日期：2026-08-03
- 背景：直接用用户整句对话搜索会引入噪声；单一外部来源在受限网络中容易超时；刷新或重复点击也不应反复产生网络请求。
- 决策：先从已校验科研画像确定性生成只读检索计划，再由用户确认来源后调用具有 `READ + NETWORK` 权限的 `academic_search` Tool。首批来源仅允许 OpenAlex、Crossref 和 arXiv，并行执行且独立报告状态；EvidenceBundle 保存到应用 SQLite，相同会话、规范化查询和来源组合在 TTL 内复用。
- 备选：直接搜索原始消息；让模型自由选择全网来源；单源串行重试；只返回临时响应而不保存结果。
- 影响：检索范围、失败和证据边界可审计，部分来源故障不会使整个请求失败；代价是要维护来源适配器、缓存失效和持久化契约。当前仅采集元数据及来源提供的摘要，不声称阅读全文。

## 新决策格式

需要记录 ADR 的情况包括：新增不可轻易替换的基础依赖、改变分层或公开接口、引入持久化/身份/部署方案、扩大工具权限、改变 Event 或人工确认语义。

```text
### ADR-NNN：标题

- 状态：Proposed | Accepted | Superseded | Rejected
- 日期：YYYY-MM-DD
- 背景：需要解决的问题和约束
- 决策：选择了什么
- 备选：考虑过哪些方案
- 影响：收益、代价、风险和迁移方式
```

小型、可逆且不影响架构边界的实现细节留在 PR，不需要 ADR。
